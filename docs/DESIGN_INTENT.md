# Design Intent Registry (Production)

> This file lists deliberate behaviour in Production. A row is added or changed only after the change has been manually tested on Development and the release is ready. It is not a list of known problems.

## How to use this file

- It describes what Production does on purpose, so a future person or AI reading the code does not "fix" or "clean up" something that is deliberate.
- Source of truth for every row is the Production code (branch `main`: `src/`, `supabase/functions`, `supabase/migrations`), plus read-only catalog checks of the Production database (table, constraint, trigger, function and storage-bucket definitions, and the `pricing_rules` configuration row). No customer data and no secret settings values are recorded here.
- "Where" gives a file and line (or a table, function, constraint or trigger name). Line numbers are approximate and drift as files change; the file and symbol name are the stable reference.
- "Change needs owner approval?" is `yes` for anything involving money, legal text, customer-facing rules or copy, security, or data retention, and `confirm` for everything else (ask the owner if unsure).
- Values that live in database configuration (for example the `pricing_rules` row) can be edited by the owner in the admin screens; the value shown is what Production held when this file was written.
- There are no automated tests in the Production snapshot, so no behaviour is pinned by tests.
- Every row was checked claim by claim against the `main` code and the Production catalog on 2026-10-25; where a code comment does not state a reason the column says "not stated".
